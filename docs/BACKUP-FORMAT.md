# KumaLift Backup File Format Specification (.kumalift)

## 1. Overview
KumaLift uses an offline-first, local-storage backup container format designed for privacy, long-term integrity, and cryptographic authenticity.

The file extension is `.kumalift` (binary container) or `.json` (legacy plaintext).

---

## 2. Binary Container Structure

A valid `.kumalift` package begins with a 6-byte header:

```
+---------------+---------------+---------------+-------------------------------+
|  Offset 0..3  |   Offset 4    |   Offset 5    |       Offset 6..End           |
+---------------+---------------+---------------+-------------------------------+
|  Magic Bytes  | Format Version|  Flag Byte    | Payload Data                  |
|  "KLBK"       |     0x01      |  (bitfield)   | (Plaintext or Ciphertext)     |
+---------------+---------------+---------------+-------------------------------+
```

### 2.1 Header Fields

1. **Magic Bytes (4 bytes):**
   - ASCII characters `K`, `L`, `B`, `K`
   - Hexadecimal: `0x4B, 0x4C, 0x42, 0x4B`
   - Identifies the file as an official KumaLift backup container.

2. **Format Version (1 byte):**
   - `0x01` (Version 1).
   - Reject backup files where version is greater than currently supported version.

3. **Flag Byte (1 byte bitfield):**
   - **Bit 0 (`0x01`) - Encryption Flag**:
     - `0`: Payload is unencrypted UTF-8 JSON.
     - `1`: Payload is encrypted with AES-256-GCM.
   - **Bit 1 (`0x02`) - Key Source Flag**:
     - `0`: Password-derived key (PBKDF2-HMAC-SHA256).
     - `1`: Device hardware Keystore key (`AndroidKeyStore`).
   - **Bits 2..7 (`0xFC`)**: Reserved for future extensions (must be `0`).

---

## 3. Payload Formats

### 3.1 Plaintext Payload (`flags & 0x01 == 0`)
Bytes immediately following Offset 6 represent standard UTF-8 encoded `KumaBackupData` JSON.

```
Offset 6..EOF: UTF-8 encoded JSON string
```

### 3.2 Password-Encrypted Payload (`flags & 0x01 == 1` and `flags & 0x02 == 0`)

```
+---------------+---------------+-----------------------------------------------+
|  Offset 6..21 | Offset 22..33 | Offset 34..EOF                                |
+---------------+---------------+-----------------------------------------------+
|  Salt         | IV / Nonce    | AES-256-GCM Ciphertext + 16-byte Auth Tag     |
|  (16 bytes)   | (12 bytes)    |                                               |
+---------------+---------------+-----------------------------------------------+
```

1. **Salt (16 bytes):**
   - Generated using a cryptographically secure random number generator (`SecureRandom`).
2. **IV / Nonce (12 bytes):**
   - 96-bit unique IV generated per backup using `SecureRandom`. Never reused.
3. **Key Derivation (PBKDF2-HMAC-SHA256):**
   - Algorithm: `PBKDF2WithHmacSHA256`
   - Iteration Count: `600,000` (OWASP Recommendation for password hashing & key derivation).
   - Key Length: `256 bits` (32 bytes).
4. **Cipher Algorithm (AES-256-GCM):**
   - Transformation: `AES/GCM/NoPadding`
   - Authentication Tag: `128 bits` (16 bytes), appended at end of ciphertext.
   - Additional Authenticated Data (AAD): Optional binding to container header.

### 3.3 Hardware Keystore-Encrypted Payload (`flags & 0x01 == 1` and `flags & 0x02 == 1`)

```
+---------------+-----------------------------------------------+
|  Offset 6..17 | Offset 18..EOF                                |
+---------------+-----------------------------------------------+
|  IV / Nonce   | AES-256-GCM Ciphertext + 16-byte Auth Tag     |
|  (12 bytes)   |                                               |
+---------------+-----------------------------------------------+
```

1. **Key Storage:**
   - 256-bit AES key securely held inside `AndroidKeyStore` under alias `"kumalift_auto_backup_key"`.
   - Key never leaves hardware enclave (TEE/StrongBox).
2. **IV / Nonce (12 bytes):**
   - Unique 96-bit nonce generated by Cipher during encryption.
3. **Ciphertext:**
   - AES-256-GCM encrypted UTF-8 JSON payload with 128-bit authentication tag.

---

## 4. Backwards Compatibility & Error Handling

1. **Legacy JSON Files:**
   - Files beginning with ASCII `{` (0x7B) are recognized as unencapsulated legacy JSON backups and parsed directly.
2. **Authentication Failure:**
   - If an incorrect password is provided or ciphertext has been altered, GCM tag verification will fail (`AEADBadTagException` / `BadPaddingException`).
   - The application reports a localized error (`strings.backupInvalidJson("Incorrect password or corrupted backup file")`) and aborts without modifying database state.
3. **Safety Snapshots:**
   - Before performing a `REPLACE` restore operation, an automated pre-restore safety snapshot of current data is created and saved to local SQLite.
